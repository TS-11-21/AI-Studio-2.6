1. Prepare before connecting an assistant
Start with one working coding assistant, then add research or animation members. A long list of installed tools is not proof that an assistant is connected.
Prepare your assistant and your own account on this computer. Automatic execution requires the relevant CLI or a program that implements the handoff protocol. A desktop chat window alone should initially use desktop manual handoff. Handle official sign-in, two-factor authentication, and authorization dialogs yourself.
Prepare only the tools this task needs. A Godot project needs Godot. Blender animation needs Blender and the appropriate MCP service. A general software task does not need Blender just for the sake of setup.
Open the connection page. Use “Roles and connections” (角色与接入). Release candidates offer “First-use setup / Configure installed tools and models” for installed executable paths. The personal desktop version uses its existing local configuration; do not copy private configuration from a commercial candidate.
Assistant subscription allowances are not included in the USD budget
USD on these pages covers API costs recorded in the local ledger only. If a subscription member shows “Station budget unavailable; your subscription allowance applies,” no dollar cap is being configured for that membership. It does not mean zero usage or unlimited usage. Check remaining tokens, rate limits, or time-window allowances in your provider account when the provider does not expose them here.
This software connects existing AI coding assistants so that they use their own tools and accounts. It does not sell model or API credits. Claude Code using your existing API / gateway can still incur API charges. Desktop handoffs, external programs, and their costs need separate verification; do not relabel them as a subscription allowance.

3. Register an assistant in Roles and connections
Click “＋ Add assistant” (＋ 添加智能体). If assistant presets are available, select a native CLI or desktop manual preset matching your real installation. A desktop preset is not a CLI. Presets fill fields; they do not install software, sign in, or send model requests.
Enter a stable, unique assistant ID, such as my-codex or my-claude-art. A name does not verify an account. Select the actual execution adapter: native automatic CLI, desktop manual handoff, research API, and external protocol program are separate routes.
Set the model, or leave it empty to inherit the registered default. Use a model actually available to your account; an invented model name does not establish a subscription.
Select available tool types: gameplay / code, animation / assets, integration / checking, and research. A checkbox proposes a task route; it does not install tools or prove permissions.
Use a settings reference only for an existing non-sensitive configuration ID. Enter a compatible endpoint where necessary; an endpoint field is not a key field.
Click “Save assistant.” Registration does not issue a model request. Then choose that assistant for a new pipeline or a specific member.
Changing default connections affects later configuration. A started pipeline uses its own frozen snapshot. Changing global defaults must not silently switch the account or model of an executing member.
4. Sign-in, keys, and local privacy
For the Codex subscription route, complete your own ChatGPT / Codex sign-in. This route does not require switching to an OpenAI API key, and the software does not handle your password or two-factor authentication for you.
The current native Kimi route accepts an explicitly managed OAuth subscription configuration only. Sign in to the official Kimi program first and select a configured model. API keys, custom gateways, or mixed API configuration are not silently treated as membership. Selected subscription credentials are copied only to the private configuration for the current worker; account secrets are not written to the task packet.
For a route that needs a key, use “Set credentials” on its assistant card and the separate password field. If you select local remembering, the Windows version encrypts it in the private credential area. Different providers need their own matching credentials; a default gateway key is not a universal key.
Keep passwords, tokens, and API keys out of goals, member assignments, ordinary JSON settings, handoff files, and screenshots.
Providers determine accounts, subscriptions, model availability, and their charges. Saving a setting in this software does not open an account.
External desktop assistants control their own project permissions and conversation retention. This software does not offer an absolute bypass-prevention or anti-cracking guarantee.
5. Configure tools and check connections
In “MCP plugins,” add or import a trusted MCP server configuration, select its tool types, and enable it as needed. Tools are filtered for the current member; a research-only member should not receive every project-writing tool.
Reference sensitive environment values as ${ENV_VAR}, then set the real value through the plugin’s private variable entry. Keep clear-text secrets out of public configuration.
First click Check connection on the assistant card. Local checks verify CLI, sign-in records, settings, or configuration. “Locally ready / configured” is not proof of a successful model call.
If a Model test confirmation is offered, check the exact assistant, model, and test allowance. A metered API test sends a request and needs separate explicit approval; do not repeatedly incur test charges during setup.
Keep Blender safe mode enabled.
The repaired verification baseline uses Blender 5.2.2 and compatible native scene / render APIs. Confirm the isolated file and worker identity before writing. Reload the saved source to check persistence; a save acknowledgment or an in-memory image count alone does not prove completion.
If the safety layer rejects a script, have the assistant correct the script. Do not disable safe mode. Use the assistant’s ordinary file tools for manifests, declared input-hash adoption records, and explanatory files. Do not force a Blender script to import forbidden modules or execute text datablocks.
6. Desktop manual handoff and connection failures
Manual desktop handoff saves the current task packet and enters “Waiting for desktop handoff.” Perform the task in the original assistant window, then return real files and a result using the completion template and location supplied by that packet. No model is repeatedly polled while waiting.
Task, station, member, provider, exchange, and plan identity must match the current packet. Do not substitute another pipeline’s result, an old revision, or a sentence saying “done.” Editing the task can invalidate an old packet; use the current one. If the return protocol is unclear, begin with a supported native automatic route.
One offline assistant does not erase an independent station’s completed work. Independent branches can continue; dependent stations still wait and cannot claim integration is complete. If a paid call was dispatched but its cost is unknown, that pipeline stops further paid work until the actual cost is reconciled. Other pipelines have separate ledgers.

Assistant compatibility update: conditions and handling
Routine updates to a registered assistant do not require a simultaneous AI Studio update when its execution interface remains compatible. A changed version directory alone does not require reinstalling this software. This is not a promise of automatic support for every new version or assistant.

Recovery applies only when the current Windows user's absolute path to the official managed Codex executable is missing and has the expected layout. It checks real executables and a valid OpenAI signature within the same managed-directory boundary, and requires one unique valid candidate. Existing executables, custom paths, relative commands and another user's directory are not automatically replaced. Ambiguous candidates, a mismatched signature or an out-of-boundary path stop the connection for review; an arbitrary executable from PATH is not substituted. Original trailing arguments and account, model, billing and MCP settings remain unchanged. Recovery does not replace sign-in, membership allowance or paid approval.

Actual interfaces, model settings, permissions and tool/MCP compatibility must still be checked for Claude Code, Kimi and external commands. Successful help or version output is not a model/MCP end-to-end pass. A third-party interface or output-protocol change may require an adapter revision. Manual desktop handoffs still return genuine task packages and are not presented as automatic execution.

A failed connection preserves saved work and puts its dependent tasks into waiting. Independent stations whose dependencies are satisfied may continue within computer resources, assistant allowance and cost-reconciliation constraints. After resolving the connection, review the state and explicitly resume through the interface. Paid approval and cumulative accounting are not reset by a path update.

Register an external protocol program with an absolute path to a real local executable, rather than a relative command or a .cmd, .bat or .ps1 launcher. Trailing arguments are retained. Preflight uses the same command validation as execution; a configuration pass is still not an end-to-end pass for the third-party model, permissions or return protocol.
